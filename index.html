How the test would work

AI plays the two participants. A language model is software that generates text in response to instructions and information. In the proposed simulation, two separate model sessions would take the roles of a family member and a frontline worker. Each role-based participant is an AI agent: it can send messages and request actions through the tools available to it.


The study defines the setting. Researchers specify the case, program rules, available documents and how the simulated application system responds. The AI chooses what to say, ask or attempt within that setting. For example, it can try to submit proof of address, but the application tool determines whether that attempt succeeds. Cases and constraints would be grounded in documents and fieldwork, with hypothetical variations identified separately.


Each side gets different information. The family’s brief describes its circumstances, knowledge and practical constraints; the worker’s describes the case information and working conditions. Neither sees the other’s private brief. They take turns responding to messages and tool results, so a document lookup or failed application step can change what happens next. The full exchange and resulting changes in case status are recorded.


Repeat, compare and check. Language models can produce different responses to the same situation. Repeating a case lets researchers examine a range of paths; changing one condition then shows how that range changes within the simulation. Researchers would check the paths against the rules and evidence from workers and families to distinguish administrative obstacles from model errors. Simulated frequencies alone do not estimate how often real people encounter a problem.
